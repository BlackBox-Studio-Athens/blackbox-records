# Design

## Context

**Final shipping authority, 9 October 2026:** all validated PRD variants share the existing assumed profile. New agreements charge one aggregate order fee: €3 for 1–4 validated cart units, €6 for 5–8 or €10 for 9 or more. Count cart units without inferring disc metadata. New `manual` classification leaves actual parcel selection/count to offline fulfillment and removes the old nineteen-unit single-parcel order ceiling. Preserve stock/cart/price/configuration guards, all old references/accepted holds and legacy Small/Medium/null meanings. Actual measurements remain Unknown. The researched two/six-unit multiple-parcel algorithm is discarded as the desired implementation. New release/hosted proof is pending; deployed 886a6e3 retains the earlier two-product/€2.50–€3.50 scope.

**9 October 2026 latest owner selection:** new checkout agreements use explicit `NO_TAX_COLLECTED` under the existing actual natural-person seller, preserving gross prices and recording actual zero collection without exemption/registration/compliance claims. The [VAT change](../greek-vat-and-shipping-charges/design.md) owns the versioned implementation and affected sandbox proof. This supersedes earlier requirements to retain taxed-only reconciliation or obtain a positive live tax calculation for the newly selected mode; genuine seller/public identity, provider capabilities, receipts, monetary integrity and final launch approval remain required. Historical inclusive agreements keep their stored policy and actual amounts. No catalog or account recreation is authorized by this behavior change.

See [proposal.md](proposal.md) for scope and [evidence.md](evidence.md) for dated observations. The shop is not live. Stripe owns payment objects and prices; D1 owns current catalog links, stock and order history. The Worker has one Stripe key and one webhook signing secret per environment, so the switch uses a short maintenance window.

## Goals / Non-Goals

**Goals:** A technically verified destination account with ordinary receipts, preserved commerce data, repeatable cutover and the owner's uncapped selling handoff after readiness.

**Non-Goals:** New payment behavior, catalog reseeding, speculative customer transfer or dual-account infrastructure. IRIS remains deferred; the owner's risk acceptance is recorded in evidence.

## Decisions

### 0. Use representative UAT fixtures and exact PRD data

The subsequent 2026-10-08 user instruction supersedes accurate historical UAT migration as an acceptance prerequisite. UAT may use approved representative catalog/stock/order fixtures; reuse the staged objects and existing evidence, retain unknown historical test cases without blocking the switch, and avoid repeat exhaustive UAT reconciliation. Correct account/mode, credentials, security, executable rollback, signed delivery and representative payment integration remain required. This authorizes no wipe/deletion or silent weakening of command safeguards. Prefer the simplest supported account/configuration switch and fixture recovery proof; an existing conservative manifest may be reused without making its historical fidelity a completion gate.

PRD retains exact authoritative catalog, prices, stock, orders, payment history and all protected-data preservation. The exhaustive source inventory, reviewed manifest, drift checks and preservation procedure below remain mandatory for PRD. Shared tooling used in UAT keeps its intrinsic write preconditions; this planning distinction adds no bypass flag or generic migration framework.

## Migration Plan

Execute this procedure once for UAT, then for PRD after technical UAT acceptance. Apply decision 5's current scope. Fiscal automation and actual Tax evidence remain deferred; assumed packing needs executable support, and provider calculations, public-content, payment and recovery checks retain their specific acceptance requirements.

1. **Prepare.** Recheck accounts and current inventory; create/resume destination Products/default Prices from the manifest before creating its endpoint.
2. **Freeze and drain.** Coordinate with `release-uat` or `release-prd` for the target environment. Manual provider smoke has its own `uat-provider-smoke` group, runtime Content/Items writes take no release lock, and `blackbox-release` belongs only to Holding Page. Stop new conflicting work and wait for active work to finish; a release lock alone is insufficient. Close checkout, freeze catalog/publication writes, and resolve source Sessions, holds, pending payments, CatalogOperation leases and payable webhook retries. For PRD, verify the launch plan's task 4.1 guard suppresses availability-alert sends before rebinding; closing checkout alone currently does not stop them. Assign retained review/history handling and keep unrelated delivery recovery running where safe.
3. **Capture and stage.** Revalidate the manifest; record source SHA, Worker/content identities, protected fields and rollback references. Disable an existing source endpoint only after drain. Create the target account webhook with the exact Worker URL, required event set and the application's pinned payload version (observed `2026-08-26.dahlia`). Capture its secret, immediately update `disabled=true`, and verify status. Stripe v1 supports disabling through [update](https://docs.stripe.com/api/webhook_endpoints/update), not [create](https://docs.stripe.com/api/webhook_endpoints/create); permit no destination payment/catalog activity in that interval.
4. **Switch.** Update the named GitHub stores, install the matching Worker values coherently, then apply the catalog manifest. Verify account/resource identity, every current link and protected fields. Any failure leaves checkout closed.
5. **Rehearse recovery in UAT before events.** Before signed probes/history advance or any destination payment, restore coherent intended source configuration/catalog links and reapply the same journaled target state. Verify no duplicate objects or lost history. The captured endpoint-bound source signing reference is available privately; opaque former deployed equality is not asserted or an extra UAT historical gate. Actual recovery and signed delivery must still pass. PRD retains exact configuration/data recovery requirements.
6. **Prove delivery.** Enable the target endpoint only after bindings agree. Generate an approved reversible catalog event and replay it; verify signatures, reconciliation and no duplicate effects, then restore probe metadata. Run the existing runtime/PMC/webhook/catalog checks. Do not fabricate live paid orders.
7. **Release the window.** Open only the approved UAT test window. PRD retains `native_checkout_enabled=false` and absent `PRD_LAUNCH_APPROVED`. Check release credential persistence and hand evidence to the owners above.

**Rollback:** The implemented inverse path is **pre-event** apply→restore→reapply, before protected webhook history advances or any destination payment. Hold the freeze, disable the destination endpoint, restore coherent source configuration and inverse catalog fields, then restore its matching endpoint and verify identity/data. Signed probes advance protected history, after which the old manifest refuses restore; ordinary target-state planning cannot construct an inverse successor and no successor-baseline recovery is implemented. Thereafter keep checkout closed and repair forward while preserving both histories. A source configuration restore alone while D1 remains target-bound is not recovery. Bound or resolve this limitation for exact PRD readiness; do not add a UAT historical-audit gate. The [prepared procedure](../../../.codex-artifacts/stripe-migration-delegation/uat-configuration-next-mutation-20261008.md) records the executable scope and limits, and the [closed UAT result](../../../.codex-artifacts/stripe-migration-delegation/uat-closed-rehearsal-20261008-result.json) retains completed recovery across all 107 prepared bindings. The [accepted Fast UAT result](../../../.codex-artifacts/stripe-migration-delegation/uat-fast-finish-20261008-final.json) subsequently repaired all seven PWYW snapshots and passed signed reconciliation/replay/cleanup plus the two core paid cases, completing 3.2/3.3. UAT has crossed the event/payment boundary: its old inverse is forbidden, checkout is closed and recovery is target repair-forward. Broader UAT and exact PRD work remain open under the existing plan.

## Risks / Trade-offs

- **New source obligations** → Refresh the dated empty-live inventory at cutover; resolve any new activity before switching. Revise scope only for an observed need.
- **Drift during a multi-system switch** → One operator, short write freeze, source preconditions and a resumable journal.
- **Unknown Tax or physical facts** → Retain the owner's assumptions/deferrals, report exact provider or executable gaps, and preserve truthful evidence. Enabled payment flags and synthetic tests cannot establish compliance or measured packing.
- **IRIS deferred** → Carry the owner's dated decision and known risk into launch evidence without claiming IRIS compliance.
