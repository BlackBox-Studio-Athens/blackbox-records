# Design

Use optional top-level action publish/withdraw on existing publication review and submission contracts; absence means publish. Withdrawal accepts Distro only and requires a reviewed snapshot baseline. Review shows accepted content becoming absent without requiring publication-complete draft fields.

Validate every selected revision before any transition. Retain operation identity, accepted revision, native version and original draft identity. Pause linked commerce options through the existing lifecycle guard, then native-unpublish without overwriting private drafts. Recovery checks the retained post-transition revision; a lost native response can be recovered only from exactly one native version increment, cleared live pointer and unchanged retained draft content. Later edits reject activation.

Remove exact records and their Store Item identities from the accepted snapshot. Validate homepage/store rendering and withdrawn product/checkout routes returning 404 through the existing private renderer. Reuse immutable storage, compare-and-swap activation, public confirmation, journal and bounded retries. Keep historical accepted snapshots and media.

Prepare on canonical main, validate Local, release an accepted UAT candidate and promote the paired PRD artifact through the normal workflow. Each environment owns its CMS IDs, catalog bindings and publication baseline. Record receipts and before/after stock/order evidence. Do not copy environment data or publish unrelated drafts.
