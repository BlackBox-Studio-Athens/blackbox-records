## Context

See [proposal.md](proposal.md). `StoreDistroSearch.tsx` already owns search controls, exact-first matching, DOM filtering, group/format selection, coverflow transitions, and cleanup. `exact-first-search.ts` supplies the installed Fuse fallback. `/store/` is a flat server-rendered shelf with a separate coverflow activation. The shell currently mounts search only at the Distro placeholder.

## Goals / Non-Goals

**Goals:** Share the existing implementation across flat All and grouped Distro catalogs, bring All Store artwork into the first viewport, and simplify All orientation/counts while preserving shell lifecycle and catalog-price budgets.

**Non-Goals:** Search on every category page, search services/index files, relevance reordering, stock/price filters, pagination, query URLs, persistent queries, or a broad search-framework refactor.

## Decisions

1. **Extend the existing module.** Keep `StoreDistroSearch.tsx` as the provided Store-owned entrypoint. Generalize its shared control, matcher and filtering path with explicit All/Distro scope; preserve existing Distro behavior as the default. Scope selects label/root and whether format/group operations apply. Avoid a duplicate All search component, compatibility facade, registry, or plugin abstraction. Existing module ownership and entrypoints remain unchanged.
2. **Read existing cards.** Emit escaped search text from each All Store Item's title, subtitle (artist/label), and existing option/format/group metadata. Build one in-memory matcher over the full rendered shelf, including off-preview cards. Missing optional metadata contributes no text. Do not search provider IDs, prices, stock, or hidden operational fields.
3. **Preserve the matching contract.** Normalize input with the existing matcher. Use all exact substring matches if any exist; only otherwise use the current fuzzy fallback. Filtering changes visibility, not canonical card order or nodes. Keep the existing Distro field set and grouping behavior intact.
4. **Give one controller ownership.** The active search control owns coverflow for each searchable shelf where supported; ordinary grids remain searchable with no controller. Update the existing flat All initializer so it does not attach a second controller when search owns the shelf. Search enters `search-results`, exposing every matching card; clear returns All to the complete catalog while preserving Distro's existing preview restoration semantics. A later explicit Show Coverflow action can return to preview where eligible. Empty queries on untouched activation do not expand preview. Preserve a pending first disclosure activation while the shared module loads; failed initialization restores the complete grid instead of leaving preview-hidden cards or dead controls. Mount against applied route markup without waiting for veil closure or price presentation. The catalog-category delta replaces the historical prohibition on All search; the performance delta permits module loading on these two related routes while preserving every existing disclosure budget.
5. **Keep route lifecycle explicit.** Add an All search placeholder; mount only while `/store/` or `/store/distro/` owns its respective placeholder. Load the existing lazy module on intent/activation for either supported route, not unrelated pages. Cleanup cancels pending work and restores canonical visibility before caching. Return visits start with an empty query and default preview/catalog presentation; Distro fragment navigation still applies normally.
6. **Reuse price activation.** Typing/clearing/filtering performs no network work and does not trigger another listing-price snapshot or per-card Store Offer reads. Prices update the existing cards independently. Normal links and server-rendered fallback continue to work when search fails or JavaScript is unavailable.
7. **Make the All shelf visible immediately.** The user accepted the design direction after UAT review: at 390px mobile and desktop, the initial screen contained only navigation and explanatory content. Shorten the All shelf introduction, reduce excessive vertical spacing, and make its Distro format handoff compact. Keep category links in their existing Signal rail; search and format tools belong beside the shelf, not inside that rail. Use an accessible native disclosure for the mobile format handoff if needed, preserving ordinary fragment links and no-script access. At 390x844 and 1280x800 CSS pixels, default text size and scrollY=0, show identifiable artwork from at least the first Store Item after loading settles. Preserve readable type, 44px format targets, the header/review marker, and policy links; do not meet the target by clipping content, shrinking text, or loading every offstage image. Enlarged-text/zoom layouts may scroll naturally.
8. **Consolidate All count feedback.** Preview uses one `1 of {total}`-style status, the complete catalog uses one total, and active search uses one matching-results count. Remove the redundant All intro total and separate On this shelf / Now viewing / More metric blocks. Keep Previous, Next, active identity, continuation ratio, and disclosure behavior; a total within the descriptive `View all {total}` action is allowed. Count changes use the existing accessible feedback path without duplicate announcements. Other categories retain their current presentation.

## Risks / Trade-offs

- Group-specific assumptions can break the flat shelf → exercise both DOM shapes, Distro format links, and tiny/empty catalogs with focused regression fixtures.
- Two coverflow controllers can fight → transfer All controller ownership during implementation and test one handler/controller per activation, including repeat navigation.
- Hidden state can poison shell snapshots → verify All-to-Distro-to-All, back/forward and cancellation with query reset and no duplicate controls.
- The existing Distro filename becomes broader than its name → retain the stable entrypoint for this bounded reuse slice; do not add parallel names or facades. A future explicit naming change must update module-boundary spec/manifest and all callers together.

## Migration Plan

No data migration. Implement shared scope support and markup together, run Distro regressions, All search checks and existing performance profiles, then use the normal static deployment path when authorized. Rollback both markup and shared-module wiring together. Honor the Impeccable preflight before changing visible controls and preserve the current BlackBox search styling.

Coordinate policy-link content with `complete-shopper-purchase-information`; this change owns All discovery layout only. The accepted direction does not waive the implementation-time Impeccable shape/image gates.
