## Scope and result

Tasks 2.3 and 2.4 are implemented. At this initial run, task 2.1 remained unchecked because no existing Account Analytics Read token was available. The later [owner setup](owner-setup.md) completed tasks 1.4, 2.1 and 2.2: its settings-only query confirmed both `7d` and `30d` are supported. Initial local evidence below remains distinct from that later hosted configuration evidence.

`public-commerce-http` owns the route under its existing internal entrypoint and dependencies. The existing Access JWT middleware runs before configuration/cache reads; Local retains the loopback bypass. The optional analytics configuration is typed, declared for every Wrangler target, forwarded through the existing Durable Object runtime config and included in runtime-config verification. No new module interface, dependency, KV, schema migration or scheduled job is added. Internal OpenAPI and generated client types were regenerated; no staff UI/API wrapper was implemented.

The exact consumer shape, UTC window semantics, empty state, cache behavior and safe error contract are in [design.md — Response contract](design.md#response-contract). The named Cache API cache `site-analytics-v1` stores only successful data snapshots for 900 seconds, with environment/account/site/range/day isolation. Browser responses remain `no-store`; request IDs and identity are never cached. GraphQL reads have a 10-second timeout, a 128 KiB body ceiling and schema validation. Logs and errors omit credentials and raw upstream bodies.
