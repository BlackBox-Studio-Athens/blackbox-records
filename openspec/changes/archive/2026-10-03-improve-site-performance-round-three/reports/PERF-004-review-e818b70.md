- Environment: Local production static build served by `astro preview` at `http://127.0.0.1:4321/blackbox-records/`; hosted UAT and PRD were not contacted

## Summary

On an unthrottled desktop the site is fast, with LCP under 320 ms on every route. The review still found four expensive problems, each with a small or medium fix:

- Hosted images run through the Pages Function and a billed binding hop. About 1,500-5,000 first-visit page views a day would exhaust the account's Free allowance of 100,000 Workers requests, checkout included.
- The Store listing is quadratic: 2.56 s of Durable Object CPU per hosted Store render, about 10 ms after two small fixes.
- Lenis uses 12-22% of a throttled main thread while idle, and together with two CSS rule groups it stalls Distro scrolling for 230-370 ms at every scroll start and end.
- Home's mobile LCP is 3.1 s because the 77 KB brand font is discovered late; a preload should bring it to about 1.2 s.

Two correctness bugs surfaced along the way. Hosted pages never receive published purchase information because of a stale build alias (PAGES-07). The public Store Offer read reconciles with apply: true (read-store-offer.ts:110), against the checkout spec's requirement that public catalog reconciliation is mutation-free (COMMERCE-03). Each module section below lists its verified findings, their fixes and what to keep.

## Player, platform and UI primitives

Its perpetual animation loops use 12-22% of a 4x-throttled main thread while the page is idle, and its non-passive listeners turn every page into a blocking touch region. ## Evidence and limits

Every finding cites file and line. 83 of the 91 original findings were re-checked by an adversarial verifier; the 8 that were not are low-impact and marked "not re-verified". After merging 21 duplicates and adding 4 issues found during verification, the review holds 74 issues: 2 critical, 13 high, 28 medium and 31 low.

- Code intelligence: graphify (21,556 nodes, 1,523 communities) and codegraph (1,185 files, 22,963 nodes), both built from e818b70, traced call paths and reachability. Every claim was then confirmed in source.
- Build: pnpm build:web on Node 24.21.0 (2 min 26 s, 340 pages, 1,243 image variants), plus the repo's bundle-graph check.
- Browser: the repo's runtime profiles (desktop-load, mobile-load, wide-scroll, mobile-scroll), and targeted Chromium 141 traces with style-invalidation tracking, CSSOM bisection and A/B runs (Lenis aborted, class toggles suppressed, chunks preloaded).
- Server: Node 24 benchmarks of the real published reader on a 125-record snapshot built from repo content (zod with and without JIT), and Cloudflare documentation read through Context7: pages/functions/pricing, workers/platform/pricing, workers/cache, durable-objects/concepts/durable-object-lifecycle, durable-objects/platform/limits and images/pricing. developers.cloudflare.com itself was not reachable from this session.
- Process: eight module reviewers and three adversarial verifiers (runtime with the browser, bytes, server), run as workflows.

Limits:

- Only the local static build was measured. Hosted UAT and PRD were not contacted, so hosted costs come from code, Node benchmarks (not workerd) and documented Cloudflare behaviour; the public Durable Object's location and real edge hit rates are unknown.
- Google Fonts could not load here (TLS-intercepting proxy) and no backend ran, so Google-font effects and price arrival times are inferred.
- Some runs shared a 4-CPU machine with other agents. Figures are medians of repeated runs, and A/B comparisons ran within one browser session.
- Headless Chromium cannot measure GPU and raster cost (backdrop-filter, blend modes, blur); those findings stay low until checked on a real mid-range phone.
- Raw data sits in `.codex-artifacts/runtime-performance/review-e818b70/` (ignored); working notes from the review session were not retained, and no raw data is committed.
