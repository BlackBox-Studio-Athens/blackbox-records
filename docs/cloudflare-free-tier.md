# Cloudflare Free-tier operating rule

Stay on Free. Do not enable a paid plan to unblock implementation or tests.

The combined CMS Worker uses Access identity and disables Astro sessions. Its canonical `pnpm --filter @blackbox/backend build:cms` command rejects KV in source configuration and in the final adapter-generated Wrangler artifact, including environment and unsafe KV bindings. Dependency upgrades must pass that build and the existing authenticated-request no-session-cookie regression. Deploy only an artifact from a successful canonical build; direct Astro builds are not release evidence.

Before bulk hosted imports, repeated probes, recovery rehearsals, or scheduled work:

1. Rehearse locally. Inspect the final generated bindings and trace service operations, including session/cache writes triggered by GET requests.
2. Read current account-wide usage for each affected operation type. Record the target, remaining allowance, expected operations, retry/pagination/background overhead, and explicit headroom for ordinary service. Unknown usage is not permission for an unbounded hosted run; continue locally until there is enough evidence.
3. Run a small bounded pilot within that allowance, measure actual operations, and revise the estimate before the full run. Stop if observed use exceeds the estimate. Reuse completed evidence instead of rerunning a full import or probe without a concrete reason.
4. On a quota warning, pause affected bulk work and retries, inspect the cause and remaining allowance, and reduce the operation count. On exhaustion, stop affected writes until the provider's stated reset and recheck usage before resuming. Reset alone does not fix unnecessary writes.

Adding a quota-consuming binding or background job requires a documented purpose, owner, measured operation budget, confirmed Free-tier availability, and behavior on exhaustion. Reintroducing KV additionally requires an intentional change to the build guard and its test with that rationale; there is no environment-variable bypass. This policy prevents accidental recurrence, not exhaustion caused by arbitrary account traffic.

## Public delivery request budget

Owner: the public release build and renderer. For Home, Artists, Services and Store, budget a cold first visit and a warm repeat visit at one Pages Function invocation plus at most one renderer invocation per HTML document. Browser image candidates use direct Images URLs; fingerprinted scripts, styles, fonts, ESM images and every `/favicon*` asset use Pages assets. These browser asset requests add no gateway/renderer invocation. Unknown paths cost one gateway invocation and zero renderer invocations because the release builds an allowlist from Astro routes and returns `no-store` 404s before forwarding.

The local gateway regression traces one document plus four static asset requests for each cold/warm visit and records one renderer call. This is a deterministic routing trace, not an observed Cloudflare billing total. The prior code routed each CMS transformation and `favicon-96x96.png` through both gateway and renderer; the review's 20–80 calls per first visit was an estimate, not hosted measurement. Workers Cache requests still count as Worker requests even when their responses are cached ([Workers Cache pricing](https://developers.cloudflare.com/workers/cache/)).

Direct delivery removes browser proxy hops, but a cold Images source-cache miss can fetch the canonical `/media/content/<sha>` through Pages and the renderer. Account for these origin fills separately from the document's two-invocation budget; Images cache-hit behavior and actual account-wide requests remain unverified locally. After an authorized release, the bounded UAT pilot checks one cold and one warm visit to the four representative routes, recording requested resources, Worker/DO invocations, image source fills, formats and cache status against these budgets. Check remaining account-wide allowance first, reserve at least half for ordinary service, and keep the whole pilot within the existing 100-public-request ceiling. Do not warm caches or repeat visits to manufacture a hit rate.

## Published HTML storage

The `public-v2` Durable Object persists disposable rendered HTML in SQLite with an 8 MiB byte-accounted LRU and a 2 MiB entry ceiling including key and headers. Keys bind release, accepted snapshot, origin and path. The R2 pointer is read on wake; a matching stored page needs neither a full snapshot parse nor SSR. An active object's pointer refresh is single-flight at the five-second interval. A successful cache hit reads its page and updates its LRU position. Startup scans cache metadata once; insertion and eviction add storage operations. Storage failures skip this optional cache and render from accepted content.

[Durable Objects pricing](https://developers.cloudflare.com/durable-objects/platform/pricing/) confirms SQLite on Workers Free, shared daily limits of 5 million rows read and 100,000 rows written, and 5 GB storage. Cache writes and indexed LRU updates consume that allowance; include them in the pilot's operation count and preserve normal-service headroom. No KV binding, paid plan or background job is added. Public and publication objects request `locationHint: 'eeur'`; [location hints](https://developers.cloudflare.com/durable-objects/reference/data-location/) are best effort, not guaranteed European placement.

HTML retains `public, max-age=0, s-maxage=30, stale-while-revalidate=30` with weak ETags and bodyless 304 responses. [Workers Cache tag purge](https://developers.cloudflare.com/workers/cache/purge/) is documented with Free-tier rate limits and per-entrypoint scope. Runtime activation refreshes the accepted pointer through the existing service binding and purges publication-tagged HTML from the default renderer entrypoint; failures keep confirmation pending without undoing accepted content. Local alone can proceed if no edge cache API exists. UAT/PRD require successful purge. The installed emulator has no native purge API, so the short window remains until the authorized hosted pilot verifies readiness and propagation; Free availability and controlled local purge-result tests do not establish that behavior. Zone-level purge cannot invalidate Workers Cache.

## Images transformations

Cloudflare Images Free allows 5,000 unique source-and-options transformations per month, shared by UAT and PRD. Past that, new transformations fail (error 9422) while cached ones keep serving. The public renderer bounds what can consume it:

- Media URLs carry the media SHA only, so a publication, including a text-only one, re-mints nothing for unchanged images.
- `/_image` transforms only media of the live snapshot or the three most recently accepted snapshots, and only widths the image components emit (the 96 to 1800 px ladder, 144/216 gallery thumbnails, 176 cart thumbnails, 540 and each image's intrinsic `src` width). Every request snaps to one of 17 ladder rungs and uses one canonical source URL per media SHA, whatever the public hostname or legacy URL shape. Thumbnail requests snap to existing 160/240 rungs and add no width variants. The direct URL service also rejects unknown widths before emission.
- The Images source is the environment's configured `PUBLIC_IMAGE_SOURCE_ORIGIN` (its Pages origin), not the request host, so adding a public hostname keeps transformations.
- Hosted `src` and `srcset` use `https://images.blackboxrecordsathens.com/cdn-cgi/image/width=<rung>,<fixed-profile>/<canonical-source>`. Fixed profiles preserve approved semantics: WebP/default quality, editorial WebP/quality68, a single 160px WebP/quality40 blurred fill, and a single 1200px JPEG metadata ceiling. Images' default scale-down fit avoids enlarging a smaller metadata source. The legacy proxy keeps auto/default quality; undefined-format direct calls share that profile. Other qualities and formats are rejected instead of silently discarded. The [URL transformation interface](https://developers.cloudflare.com/images/optimization/features/) and [Images Free pricing](https://developers.cloudflare.com/images/pricing/) supply the syntax and quota. Private preview images and repo ESM assets pass through directly.
- When a transformation fails, the renderer serves the verified original with `public, max-age=300` and `X-Blackbox-Image: original-fallback`, never immutably, so transformations resume after the monthly reset and the edge absorbs repeats meanwhile.
- Direct browser images use a native capture-phase error listener that clears `img`/`picture` responsive candidates and fetches the canonical public original once. It also handles images that failed before the module started and images inserted by shell navigation. Cloudflare's `onerror=redirect` only supports same-zone sources and cannot restore these cross-zone Pages originals. Each fallback adds a Pages/renderer original request outside the document budget, with no Images retry; original media-SHA URLs retain their normal cache policy. Script-disabled browsers and metadata crawlers cannot run this handler, so JPEG unfurl behavior on quota exhaustion remains a provider acceptance limitation.

The conservative emitted-profile ceiling is 53 transformations per distinct media SHA per environment: 17 default WebP +17 editorial WebP68 +1 blur +1 JPEG +17 legacy auto. Normal validated browser output uses at most36; actual totals depend on each image's roles and requested candidates. This replaces the earlier17 estimate and does not increase the account's shared5000 monthly allowance. Count the union of source/options already used that month, including removed media, earlier configurations and both environments; live/recent snapshot counts alone are not a monthly usage bound. A text-only publication or hostname change adds none for unchanged sources/options. Auto's negotiated output formats count once within its profile. Direct URLs expose mutable options, so builder rejection is not a provider-side quota-abuse control; arbitrary client changes and cached retired transformations remain unverified hosted gates. Check actual account usage and ordinary-service headroom against this larger estimate before bulk imports or an authorized bounded pilot. After a hostname or Images configuration change, run `pnpm smoke:uat-static -- --site-url <public-url> --scenario image_transform`; it expects a 480 px AVIF or WebP of at most 250 KiB with immutable caching.

## Incidents

Incident evidence: [UAT editorial import](../openspec/changes/replace-sveltia-with-emdash-operations/uat-editorial-import-evidence.md). Cloudflare reported the account's daily KV PUT allowance exhausted on 2026-09-13. Redundant Astro sessions were a verified contributor; the retained evidence does not attribute every account write.

Recovery was verified on 2026-09-14 at 01:01 UTC. Account-wide KV analytics reported no operations for the new UTC day before a bounded probe. One uniquely named diagnostic key in the existing M1 UAT session namespace was written with a 60-second expiry and read back successfully (HTTP 200 for both; exact value match). This used one PUT and one GET, with no retry, namespace creation, binding change, or plan upgrade. Evidence: `.codex-artifacts/emdash-m1/kv-reset-verification.log`. Analytics can lag; this is proof of restored access, not an exact remaining-quota guarantee. Keep the no-KV CMS guards and preflight budgeting rule in force.
