# Validation and release feedback

## Historical baseline before the Nx migration

The corrected 2026-09-19 through 2026-09-26 workflow sample contains 28 UAT candidate attempts: 22 successful and 6 failed. Successful UAT attempts had 955 seconds median execution time (p75 1092s, p90 1163s), 3 seconds median queue time, and 984 seconds median from run creation to promotion readiness. Early UAT quick-check timing is unavailable because that stage did not exist. PRD promotion had 11 successful, 1 failed, and 1 cancelled attempt, with 183 seconds median successful duration. Run creation is the available proxy for push time. Unrelated workflows are excluded.

Across those attempts, jobs accumulated 25,910 runner-seconds for UAT and 2,241 for PRD promotion. Setup used 4,539 and 651 runner-seconds; artifact transfers used 1,364 and 230. Successful-attempt median setup time was 60s for UAT and 28s for PRD; median transfer time was 12s and 9s. Setup/transfer elapsed measures the largest per-job sum of matching active step durations, excluding post-job cleanup and gaps between steps. Runner cost sums all jobs, including failed attempts. These differ from total workflow wall time.

The initial local full-validation run did not produce a completed summary within WebStorm's 120-second wait. Its output showed `environment:model:verify` in 1.8 seconds and `check:boundaries` in 36.9 seconds. Local total and first-failure time for that attempt are unavailable. No updated hosted sample exists yet, so no hosted speed improvement is established.

Historical local samples are not post-Nx measurements: full validation completed in 408.8s; a targeted run completed in 93.7s with explicitly reduced coverage; two implementation-tree runs completed in 176.6s and 247.9s. These are individual, non-comparable samples, not before/after medians. Keep them as historical context only.

## Current local validation

Nx 23.2.1 owns affected selection, task scheduling and deterministic local caching, without Nx Cloud. `project.json` files define source and integration-test roots, targets and task inputs. Vitest discovers tests within those roots. Backend module targets depend on their test projects through native Nx task dependencies; the full run deduplicates shared integration suites. This keeps test imports in the affected graph without creating production-module cycles. `*.worker.test.ts` files use the Cloudflare pool, `*.request.test.ts` files use the browser API mock setup, and other tests use Node. The Worker pool has no unused application entrypoint; tests import the runtime they exercise and retain real D1 migrations and transactions.

[feedback-policy.json](../feedback-policy.json) classifies every root command and holds the slot budget, deny rules and lease times; scripts and agent hooks read it. Release-tier commands are refused locally until the maintainer runs `pnpm feedback:grant-full <minutes>` (`--revoke` ends it); the grant covers every checkout until it expires. The script guard fails closed: it also covers whole-package suites started from a package directory or filter, and script files that do release-tier work when started with `node`. Agent hooks for Claude Code and Codex deny raw runners that bypass the guard (by name or file path, including direct `nx affected` and `nx run-many`) and any attempt to issue a grant, and record denials in `.codex-artifacts/feedback-guard/denials.jsonl`. Claude Code picks up hook changes in running sessions; restart Codex sessions.

- `pnpm test <module|file>` runs one project's tests or the tests a file affects; it takes a machine slot only when one is free and never waits. `pnpm test:watch <module>` takes no slot. Bare `pnpm test` and `pnpm test:changed` select affected tests and wait for slots.
- `pnpm validate` runs affected module tests, package lint and type checks and the required architecture checks. Locally it takes every free slot of the three shared by all checkouts of this repository (the measured optimum for one run) and passes the count to Nx as `--parallel`; with none free it waits in arrival order and prints `Waiting for a validation slot; held by <checkout> (pid <n>, <label>)`. It then formats files changed since the affected base and untracked files in place (CI only checks formatting), identifies source as `HEAD` plus the changed files git reports, and sets `NX_PLUGIN_NO_TIMEOUTS=true` so a slow plugin worker does not fail a task. Local runs pass `--nxBail` to stop at the first failure; CI (`GITHUB_ACTIONS=true`) omits it, because bail kills tasks already running and Nx then reports them as failures too, so each CI task reports its own result and any failure still fails the run. If another thread edits the tree during the run, it reruns the same selection once, restoring unchanged tasks from cache, and reports `invalidated` only after a second change. `pnpm validate --plan` prints the task graph without taking slots or running tasks. A second validation of the same checkout waits for the running one (`Waiting for the validation already running in this checkout (pid <n>).`); a lock left by a killed run is taken over automatically.
- The summary in `.codex-artifacts/validation/<run>/summary.json` adds `slots`, `lockWaitMs`, `formatted` and `passes`; a rerun also records `supersededPhases` and `firstPassSourceChanges`. Local evidence remains partial where browser, provider, publication or release acceptance was not run.
- Root contract tests run as five cached groups, `workspace:test-agent`, `test-release`, `test-runner`, `test-boundaries` and `test-content`, each with declared inputs in the root `project.json`; `workspace:test` is their alias and `pnpm test:contracts` runs all five. Root lint, architecture and environment tasks also declare their inputs; only `format` keeps whole-repository inputs. An edit limited to documentation or OpenSpec change files therefore executes only formatting, plus `workspace:architecture` when it touches an agent guidance document. The root `package.json` is an input of root tasks only: a script edit there reruns root tasks and leaves module tests and package lint and type checks cached. `scripts/check-module-projects.mjs` fails when another root task hashes documentation or OpenSpec change files or when the shared `toolchain` input lists the root `package.json` again, and the weekly uncached CI run below catches an input declared too narrowly.

### Module iteration

- Find the nearest `project.json` to identify a module; inspect its effective Nx targets with `pnpm exec nx show project stock --json`.
- Run `pnpm test stock` for a focused pass or keep `pnpm test:watch stock` running while editing. The native watch target works in agent and CI sessions. Use `pnpm test:changed` or `pnpm validate` afterward to check affected consumers.
- Co-locate backend tests next to the module source, such as `apps/backend/src/application/commerce/stock/*.test.ts`; cross-module tests go under `apps/backend/test/integration/<feature>/`. Use `.worker.test.ts` and `.request.test.ts` for Worker and request runtimes. Prefix Astro page tests with `_`, such as `_catalog-media.test.ts`.
- Native Vitest discovery accepts `.test` and `.spec` TypeScript files. Keep root-level contract tests conservative; add behavior tests to the owning module. A new root test joins exactly one group's `package.json` list, and that group's inputs must cover the files it reads.
- A new module needs a native Nx root and test target, declared non-import dependencies, and matching boundary policy. The test inventory fails when a test is omitted from its root or appears more than once.
- `test:changed` and `validate` use `origin/main` by default; `--since` overrides the base. Slots set task concurrency; the validation wrapper rejects the obsolete `--jobs` option. Full CI and applicable browser acceptance gates remain required.

The existing `--scope` compatibility path is partial. Use named Nx projects and affected commands for current guidance; do not infer complete scope coverage from a legacy scoped result.

For public frontend edits, check `pnpm site:dev:status`, reuse the server if present, otherwise start `pnpm site:dev:bg`, and inspect the affected route. Use `pnpm dev` for CMS, checkout or publication behavior. The site uses this checkout's port ([local runtime](agent-reference.md#local-runtime)); Astro rejects an occupied port instead of moving to another one.

Record post-migration local time to first failure and total duration separately from hosted queue, setup, transfer, runner cost, UAT live, candidate-ready and promotion-ready time. The September 29 migration measurements and their limits are recorded in the change's `nx-migration-validation.md`. Compare samples with equivalent selection and report counts; do not infer speed gains from the task graph. `pnpm feedback:report` (read-only; `--since <ISO date|Nd|Nh>`, `--top <n>`, `--json`) prints executed Nx task time by category, cache hits and the slowest tasks from Nx task history, guard denials by rule, and a weekly timeline (validations, share passed, median and p75 duration, slot wait, denials, e2e runs). The timeline reads `history.jsonl` in the shared state directory, to which every local validation, guard denial and local e2e run appends one line; the 2026-10-01 baseline is in the `enforce-scoped-feedback-loop` change's `design.md`.

## Hosted release feedback

A push to `main` runs `check-candidate`, `e2e`, `staff-previews` and the content-free `build-uat` in parallel; `deploy-uat` needs only `check-candidate` and `build-uat` and is the only job that mutates UAT. Failed validation cannot reach deployment. The browser suites run beside the deploy: a failed e2e shard or staff preview leaves UAT deployed but turns the run red, and a red run cannot be promoted. The build holds no secret and restores no CMS content or media. `check-candidate` runs `pnpm validate:checks` without an Nx cache, because Nx does not support reusing a local cache on another machine. It is the push's critical path (4m24s of Nx time in run 37475496472, 64% of it recoverable by parallelism), so it runs as three matrix legs on separate runners, `--part=lint`, `--part=typecheck` and `--part=tests` (unit tests), each with `NX_PARALLEL=4` to match the public runner's 4 vCPUs instead of `nx.json`'s local default of 3. `deploy-uat` needs all three legs. Step durations come from the Actions API (`gh run view --json jobs`), so the workflow keeps no timer steps.

The browser suites run on every push, not at promotion, and gate promotion rather than the UAT deploy. The e2e suite builds the Local fixture with `pnpm build:web`, so route isolation and the eager bundle budgets gate every push, and runs as four Playwright shards on separate runners against the built preview, each with four workers (the runner's vCPUs; Local `astro dev` keeps two), and retries a failed test once in CI, so a network hiccup is reported as flaky instead of failing the push; a test that fails twice fails the run. The staff previews run as one leg per browser, `--browser=chromium` (with the preview policy, which checks both engines) and `--browser=firefox`, against the PRD staff build; each leg installs both browsers. Neither holds a secret. `deploy-uat` runs the Pages credential check, migrations, Workers, Pages, then `verify-worker uat`, listing readiness and `verify-hosted uat`, then the UAT static smoke; a red smoke fails the run. PRD promotion (`promote-prd.yml`, no inputs) is deploy-only: `release-candidate.mjs resolve` proves from `main` that the run UAT serves succeeded on a push to `main` with its four e2e shards, both staff preview legs and `deploy-uat`, then `deploy-prd` rebuilds PRD from that SHA and deploys. Provider smoke is the manual `uat-smoke.yml` workflow in its own concurrency group; it binds `catalog-promotion-uat` and never gates a release. A weekly `full-validation.yml` run (also manual) executes `pnpm validate:full --no-cache` as the backstop for narrowly declared task inputs.

The e2e shards and the staff previews are the push's longest jobs, which is why they no longer gate the deploy. Before this change, push run 37537450513 took 14.8 minutes: `deploy-uat` waited 6:46 for the slowest browser suite, then spent 5:23 in `verify-worker`, which read the identity from a lagging Durable Object; promotion 37539133505 took 7:53. `verify-worker` now reads the Worker entry and waits up to about 2 minutes (24 retries at 5 seconds). Estimated targets, to be replaced by measured values: UAT live about 4.5 minutes after a push, the run green about 5.5 minutes, a promotion about 2.5 minutes. Record further timings from `gh run view --json jobs`: UAT live (`deploy-uat` complete) and, for a promotion, `deploy-prd` complete, each from run creation.

Each smoke suite writes its status, per-scenario results, and evidence directory to the GitHub job summary, so triage starts there before the uploaded evidence.

Build and check jobs use cancellable branch concurrency groups. `deploy-uat` holds the non-cancelling `release-uat` group, so a newer push replaces a waiting deploy and never cancels one that is mutating; `deploy-prd` holds `release-prd`; `prd-holding-page.yml` keeps `blackbox-release` alone. Monotonic run-number checks reject late candidates. Cancellation can discard builds but cannot interrupt an active mutation.

For local recovery, inspect `.codex-artifacts/validation/<run>/summary.json`, then the named failure log. Rerun `pnpm validate` after source changes. A fresh full-suite diagnosis (`pnpm validate:full --no-cache`) needs a maintainer grant; otherwise report the suspect task and its inputs. For hosted failures, inspect the run summary and the failing acceptance job's evidence, then roll back by reverting and pushing a new candidate. Never bypass release verification, reseed data or reuse incompatible evidence.
