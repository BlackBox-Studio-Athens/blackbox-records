## Local iteration and completion

`pnpm validate` is now the local completion command, using targeted checks instead of repeating the full CI suite. It compares against `origin/main` (HEAD fallback), including committed, staged, unstaged, deleted, and untracked files. `--since <ref>` overrides the base. The selected base is pinned to a commit before starting both lanes. Tests use Vitest's import graph; checks run affected-package types, changed-file ESLint, and cached formatting. Shared packages and tooling add all package type checks and repository contracts. Package configuration, content, assets, migrations, and other non-imported files broaden that package's tests. Logs and source fingerprints remain in the existing runner; `mode: local` cannot establish full release acceptance.

Use `pnpm test:changed --scope web|staff|backend|api-client` for the smallest imported-source edit/test loop. It uses native `--changed=HEAD` selection across every existing package config and exits after one run. Pass `--since <ref>` for committed changes. `pnpm test:watch --scope <package>` keeps those configs warm. These commands alone remain partial. `pnpm validate:fast --scope <package|all>` remains available when a complete package checkpoint is useful. Dynamic dependencies outside the import graph can need an explicit affected test; full CI remains the backstop.

For public frontend edits, check `pnpm site:dev:status`, reuse the server if present, otherwise start `pnpm site:dev:bg`, and inspect the affected route with the native browser. Astro hot updates avoid rebuilding or restarting the full stack per edit. Use `pnpm dev` when testing CMS, checkout, or publication boundaries. Keep browser checks proportional to the affected behavior; routing/player edits still require their documented continuity checks.

The full Local stack can own port 4321 even when Astro reports no standalone dev server. Reuse that site or stop its owning launcher before starting the frontend-only server. `strictPort` now rejects occupied port 4321 instead of silently moving to 4322. If Astro's background startup reports an early exit, the detailed diagnostic remains in `apps/web/.astro/dev.log`.

Full tests, checks and release builds run in CI before deployment. `pnpm validate:full` is the optional local full suite; its check lane puts formatting and lint before boundary/type work so failures arrive earlier. `--resume` opts into successful phase reuse and `--no-cache` forces a fresh run. Local completion and pushing require a targeted `pnpm validate` pass for the final source fingerprint and toolchain. Browser, editor, publication, and hosted acceptance remain additional when applicable.

Standalone `pnpm lint` uses that existing phase-reuse mechanism by default. Its one-phase result remains partial, and any source/configuration/toolchain/environment change or incomplete evidence forces lint to rerun. `pnpm lint --no-cache` forces a fresh run; full validation/CI still runs fresh lint by default. This avoids relying on file-only caching for type-aware rules whose diagnostics depend on imported code. `pnpm format` now invokes the installed Prettier binary directly with the existing configuration/plugin-aware cache and experimental CLI, supports explicit file targets, and honors `--uncached` with an explicit `--no-cache`.

Generated Graphify output is ignored by Git, Prettier, and ESLint, alongside the existing CodeGraph formatting exclusion. ESLint also explicitly excludes CodeGraph output. This prevents local graph caches from adding thousands of irrelevant files to source checks. The final formatter comparison excludes those generated caches from both paths.

Agents run validation through the Codex console using CMD, an explicit project working directory, and RTK output filtering. Run `pnpm validate --no-cache` for a fresh full pass; poll a long-running command until its exit code is known, then inspect the validation summary. Use PowerShell without profiles only when the command requires it. The existing **BlackBox Validate Fresh** and **OpenSpec Strict** WebStorm entries remain manual launchers pointing to committed package scripts. The old temporary configuration named **OpenSpec change passes strict validation in the authorized worktree** referenced a deleted test fixture; remove that obsolete temporary entry if it remains in local IDE history. Do not recreate the fixture or run that entry.

## Candidate stages and recovery

`pages.yml` runs `check-candidate`, `prepare-uat`, and `prepare-prd` concurrently. Every preparation job checks the immutable main source before checkout or authenticated snapshot restore. UAT inspection waits for both checks and its build; candidate assembly waits for checks and both target bundles. Failed validation cannot reach deployment or produce an assembled candidate. The tradeoff is that a failed candidate may have spent runner time preparing unused bundles.

Each target builds the public frontend once and builds staff once through the canonical combined CMS build. That staff build includes route isolation and bundle budgets for the exact target configuration. Both target jobs restore Astro's image-transform cache; only the bounded UAT save writes it. GitHub's native `hashFiles` compares the restored and post-build cache contents, skipping uploads for unchanged or empty caches and retaining the 600 MiB limit. No compiled site, Worker, validation result, or acceptance result is restored from that cache.

UAT continues through `inspect-uat-pages` and the `uat-release` reusable-workflow call while PRD preparation runs. That call inherits repository secrets. Its Worker and provider-smoke jobs bind `catalog-promotion-uat` and fail before setup/mutation if required credentials are missing. Its Pages job stays outside that environment and uses the repository Pages token. PRD promotion retains the direct jobs and schema-2 `release-<sha>` artifact; it does not rebuild. The previous reusable-workflow attempt forwarded only a named Pages token and failed with empty Worker/Stripe credentials; this call uses GitHub's documented `secrets: inherit`, with credential-presence and workflow-contract checks. Hosted credential resolution still requires observation after push.

Automatic check/build/assembly preparation uses cancellable branch-and-role groups and starts without waiting for an earlier deployment. Manual preparation gets run-specific groups. Only the `uat-release` caller acquires `blackbox-release`, holding it across all three mutation/acceptance jobs; the child declares no competing lock. PRD dispatches retain the workflow-level shared lock, as do content publication and the holding-page deployment. Immediate monotonic run-number checks reject older candidates that finish late. Cancellation can discard preparation, never interrupt the active mutation sequence.

For local recovery, inspect `.codex-artifacts/validation/<run>/summary.json` first, then only the named failure log. Rerun `pnpm validate` after source changes; use `pnpm validate:full --no-cache` for full-suite diagnosis. For hosted failures, inspect the run summary and UAT smoke evidence; prepare a fresh candidate after a rollback. Never bypass release verification, reseed data, or reuse incompatible evidence. Hosted behavior remains unobserved until an authorized push runs the workflow.
